# ESP32-S3-BOX-3B 屏幕显示架构 · 宠物表情系统

> **屏幕**: 2.4 寸 IPS LCD, 320×240, ILI9342C 驱动, SPI 接口
> **触摸**: 电容触摸屏
> **音频**: 板载双麦克风 + 喇叭（替代 ASRPRO 模块）
> **风格**: 像素复古风（32×32 像素画，8× 放大至 256×256 居中显示）——当前 MVP 先用矢量绘制，像素画为 Phase 2 目标
> **状态**: ✅ Phase 1.5 屏幕表情 MVP 已实现（LovyanGFX 矢量绘制版，文件在 `ESP32/src/desktop_pet/PetDisplay.*`）；像素画 / 动画 / 触摸 / 语音为后续规划

## 〇、当前实现状态（Phase 1.5 · 矢量画 MVP）

下方第二至九章是**完整的像素画/动画/触摸/语音规划**。当前已落地的是简化版：

- **渲染方式**: 用 LovyanGFX 以矢量图形（圆/弧/矩形/爱心）直接绘制卡通小脸，非 32×32 像素画。
- **心情 → 脸**: 8 种心情（HAPPY/NORMAL/HUNGRY/SLEEPY/ANGRY/SICK/EXCITED/LOVE），见 `PetState.h` 的 `PetMood`，由 `PetState` 状态机驱动，`PetDisplay::render()` 在 (心情/属性/眨眼阶段) 任一变化时重绘，内部短路未变化的帧。
- **驱动配置要点**:
  - SPI: MOSI=6 SCLK=7 CS=5 DC=4；写频率 40MHz。
  - **`pin_rst = -1`（Float）**: 硬件文档标 RST=GPIO48，但该板实测驱动 GPIO48 会整屏白屏，故当前保持浮空未驱动。⚠️ 待确认板子型号后重审。
  - 分辨率 320×240，旋转 rotation=1（横屏），背景色 `0xFAF7F2`（**线稿版改成米白**，原 1.5 MVP 用 `0x181C30` 深蓝）。
- **坐标陷阱（已修复）**: LovyanGFX 的 `fillRect(x, y, w, h)` 后两参是**宽/高**，不是终点坐标。曾误写 `fillRect(144,160,176,164)`，导致一张 176×164 的大黑块盖住屏幕右下角；已改为 `fillRect(144,160,32,4)`（NORMAL 平线嘴）。
- **屏幕代码文件**: `ESP32/src/desktop_pet/PetDisplay.h/.cpp`（已实现）、`PetState.cpp`（心情状态机，已实现）。
- **未实现（规划中）**: 32×32 像素画位图、触摸互动、对话气泡、ESP-SR 语音、DS1302 真实时间。
- **已实现**（线稿版 1.6 + 完整身体 1.7）: 顶部 24px 状态栏 HUD（饱食度条+好感心形+等级+时间占位）；SLEEPY 心情采用完整身体矢量图（圆胖方形+耳+眯眼+ω嘴+卷尾+Zzz，从 `image.svg` 通过 `svg2catpath.py` 自动生成 1-bit PROGMEM 位图）；其他 7 个心情暂保留按五官切换的版本。详见 §1.6 / §1.7 / [SVG导入指南.md](./SVG导入指南.md)。

### 眨眼状态机

```cpp
// 字段 (PetDisplay 私有)
unsigned long _nextBlink;   // 下次眨眼开始
unsigned long _blinkStart;  // 当前 blink 起始
uint8_t       _phase;       // 0=睁 1=半闭 2=全闭 3=半开

// 每次 render() 时调用 updateBlinkPhase(now)
if (now < _nextBlink)            _phase = 0;
else if (dt < 25)                _phase = 1;  // 半闭
else if (dt < 125)               _phase = 2;  // 全闭
else if (dt < 150)               _phase = 3;  // 半开
else { _nextBlink = now + 3000 + random(2000); _phase = 0; }
```

## 一·七、所有 8 个心情的完整身体位图（Phase 1.8）

> **详细流程见** [`SVG导入指南.md`](./SVG导入指南.md)。本节只列关键结论和数据,具体怎么从 8 个 SVG 一路变成屏幕上的猫,看独立文档。

### 背景

§1.6 用 LovyanGFX 实时画线稿版的脸(画圆/弧/线),§1.7 把 SLEEPY 一个心情换成完整身体矢量图。Phase 1.8 把这一步推广到**全部 8 个心情**:每个心情一张独立 SVG,统一用 `cairosvg` 渲成 1-bit 位图,查表渲染。

`cat_pic/` 目录下 11 个 SVG,映射到 8 个心情(剩余 3 个备用):

| PetMood | SVG 路径 | 黑点参考 |
|---|---|---|
| HAPPY | `cat_pic/happy.svg` | ~2400 |
| NORMAL | `cat_pic/normal.svg` | ~1400 |
| HUNGRY | `cat_pic/hungry.svg` | ~3300 |
| SLEEPY | `image.svg`(根目录,不是 cat_pic/)| ~1600 |
| ANGRY | `cat_pic/angry.svg` | ~2200 |
| SICK | `cat_pic/ill.svg` | ~3600 |
| EXCITED | `cat_pic/very_happy.svg` | ~1300 |
| LOVE | `cat_pic/love.svg` | ~2700 |

未用: `eating.svg` / `play.svg` / `stand_up.svg` / `stroke.svg` (预留)

### 关键结论

- **数据流**: 8 个 SVG → `svg2catpath.py` (cairosvg 渲 + Pillow 二值化) → `cat_bitmaps.h` (1-bit PROGMEM **67.5KB**,8 × 8.4KB) → `drawMoodBitmap(mood)` 查表→扫位图→画黑点
- **格式**: 320×216 1-bit MSB-first, 0=黑 1=白
- **性能**: 1300-3600 黑点 × `drawPixel` ≈ 5-8ms/帧, 0 RAM
- **位置**: x=0..320, y=24..240 (顶部留 24px 状态栏, 左上角对齐)
- **配色**: `INK = 0x222222` 墨黑, 不画 §1.6 的局部彩色(位图本身就含表情细节)
- **底部 label**: 全部统一加 `drawMoodLabel(mood)` (e.g. "HAPPY :)") ,SLEEPY 的 Zzz 在图里

### 渲染实现(当前版本)

```cpp
// PetDisplay.cpp
#include "cat_bitmaps.h"  // 由 svg2catpath.py 自动生成 (8 个 PROGMEM 数组 + 查表)

void PetDisplay::drawMoodBitmap(PetMood mood) {
    if ((uint8_t)mood >= CAT_BMP_MOOD_COUNT) return;
    const uint32_t INK = 0x222222;
    const int y0 = 24;

    // 查表: cat_bitmaps[] 本身在 PROGMEM,要 pgm_read_ptr 读
    const uint8_t* bmp = (const uint8_t*)pgm_read_ptr(&cat_bitmaps[mood]);

    for (int y = 0; y < CAT_BMP_H; y++) {
        for (int xb = 0; xb < CAT_BMP_ROW_BYTES; xb++) {
            uint8_t byte = pgm_read_byte(&bmp[y * CAT_BMP_ROW_BYTES + xb]);
            if (byte == 0xFF) continue;

            for (int bit = 7; bit >= 0; bit--) {
                int x = xb * 8 + (7 - bit);
                if (x >= CAT_BMP_W) break;
                if (((byte >> bit) & 1) == 0) {
                    _lcd.drawPixel(x, y0 + y, INK);
                }
            }
        }
    }
}
```

### 渲染分发

```cpp
void PetDisplay::drawFace(PetMood mood, const PetStats& stats, unsigned long now) {
    _lcd.fillScreen(COL_BG);
    drawStatusBar(stats, now);
    drawMoodBitmap(mood);    // §1.8 查表画当前心情位图
    drawMoodLabel(mood);     // 底部心情文字
}
```

### 方案对比(踩坑后定稿)

| 方案 | 数据 | 速度 | 视觉 | 状态 |
|------|------|------|------|------|
| 矢量 drawLine (§1.5/1.6) | 几 KB | 22ms | 1px 锯齿明显 | ❌ 弃用 |
| 1-bit 位图 (当前) | **67.5KB** (8 张) | 5-8ms | cairosvg 抗锯齿保留 | ✅ 定稿 |
| RGB565 pushImage | 1080KB (8 张) | <5ms | 完美 | ❌ PROGMEM 太大,透明处理复杂 |
| 单张位图 (§1.7) | 8.4KB | 5ms | 抗锯齿 | ⛔ 部分升级,8 个才完整 |

### 注意事项(简短版,详见独立文档)

1. SVG 必须是**真矢量** (含 `<path d="M...C...L...Z">`),不能是位图嵌入 (`<image>` 标签)
2. **PDF 多半是位图**,不能直接用,需要重新描
3. 调 `RENDER_SCALE` 提高清晰度, 调 `THRESHOLD` 控制黑白
4. 改完 SVG 跑 `python svg2catpath.py` 重新生成
5. 烧到 ESP32 前**先用 `python verify_bitmaps.py` 反渲验证**,看 `cat_pic_preview/_all_moods.png`
6. 改心情映射 → 改 `svg2catpath.py` 的 `MOOD_SVG` 列表

### 如何更换/调整心情形象

1. 在 Inkscape / Figma 画好新图,导出真 SVG
2. 替换 `cat_pic/*.svg` 或 `image.svg` (SLEEPY)
3. 跑 `python svg2catpath.py`
4. 跑 `python verify_bitmaps.py` 看反渲
5. 编译上传

### 不在 1.8 范围

- 眨眼/呼吸/挥爪等**帧动画**(位图是单帧,需要多帧 SVG 或运行时叠加)
- 触摸互动(屏幕架构文档的 P3 阶段)
- ESP-SR 语音
- DS1302 真实时间
- 运行时动态切换(需要 SD 卡 + 文件系统,Phase 3 规划)

## 二、表情像素画设计

### 设计理念

在 320×240 的屏幕上用 **32×32 像素画** 表达宠物表情，每个像素放大 **8 倍** 显示（256×256 像素区域），居中放置。

```
屏幕布局 (320×240):
┌────────────────────────────────────┐
│  LV:88  ♥:75  Lv.3   🌡26°C  14:30 │  ← 状态栏 (24px 高)
├────────────────────────────────────┤
│                                    │
│                                    │
│          ┌──────────┐              │
│          │          │              │
│          │  ◉    ◉  │  256×256     │
│          │          │  (32×32 ×8)  │
│          │   ╰──╯   │              │
│          │          │              │
│          └──────────┘              │
│                                    │
├────────────────────────────────────┤
│  "好开心呀~"                        │  ← 对话气泡 (32px 高)
└────────────────────────────────────┘
```

### 屏幕分区

| 区域 | 像素范围 | 高度 | 内容 |
|------|---------|------|------|
| 状态栏 | (0,0)→(320,24) | 24px | 饱食度条、好感心形、等级、温度、时间 |
| 表情区 | (32,24)→(288,280) | 256px | 32×32 像素画 ×8 放大，居中 |
| 对话气泡 | (0,208)→(320,240) | 32px | 宠物"说话"内容（TTS 回复文字）|

> 表情区实际占 256×256，屏幕宽 320，左右各留 32px 边距可画装饰（如耳朵、光环）。

### 表情动画帧

每个表情可包含 **多帧动画**，循环播放让宠物更"活"：

| 表情 | 动画 | 帧数 | 帧间隔 |
|------|------|------|--------|
| 所有 | **眨眼** | 正常→半闭→全闭→半闭→正常 (5帧) | 80ms |
| 大笑 | **嘴巴张合** | 大→小→大 (3帧) | 200ms |
| 困倦 | **Zzz 飘动** | Z→zZ→zZz (3帧) | 500ms |
| 吃饭 | **咀嚼** | 嘴开→嘴合 (2帧) | 150ms |
| 睡觉 | **呼吸起伏** | 身体大→小 (2帧) | 1000ms |
| 问好 | **挥手** | 手左→手右 (2帧) | 300ms |

### 像素画数据格式

```c
/* 每个像素画 = 32×32 = 1024 像素 */
/* 使用 16bit RGB565 色值 */
/* 存储在 PROGMEM (Flash) 中节省 RAM */

/* 调色板方案: 每个表情用 8-16 色调色板 */
/* 每像素只需 4bit 索引 → 1024 像素 = 512 字节/帧 */

typedef struct {
    uint8_t  id;              /* 表情 ID */
    uint8_t  palette_size;    /* 调色板颜色数 */
    uint16_t palette[16];     /* RGB565 调色板 */
    uint8_t  frame_count;     /* 动画帧数 */
    uint8_t  *frames[8];      /* 帧数据指针 (每帧 512 字节) */
    uint16_t frame_delay[8];  /* 每帧持续时间 (ms) */
} PetFace;
```

## 四、板载音频（替代 ASRPRO）

### BOX-3B 音频硬件

| 组件 | 规格 | 用途 |
|------|------|------|
| 双麦克风 | MEMS 数字麦克风 | 语音识别输入 + 降噪 |
| 喇叭 | 板载小喇叭 | 语音回复 + 音效 |
| 音频编解码 | ES8311 (I²S) | 音频输入/输出 |

### 语音识别方案

**推荐**: 使用 Espressif 官方的 **ESP-SR** 离线语音识别库

| 参数 | 值 |
|------|----|
| 库 | ESP-SR (espressif/esp-sr) |
| 识别类型 | 离线命令词识别（MultiNet）|
| 最大命令数 | ~200 条 |
| 唤醒词 | 支持自定义（WakeNet）|
| 识别语言 | 中文 / 英文 |
| 延迟 | <500ms |

> **优势**: 不需要额外硬件模块，BOX-3B 自带麦克风+喇叭全部搞定。
> **ASRPRO 仍可作为备选**: 如果 ESP-SR 识别率不够好，可以后续再接 ASRPRO。

### 语音命令（与 ASRPRO 方案相同）

命令词和唤醒词设计不变，只是实现方式从 ASRPRO 硬件模块改为 ESP-SR 软件库。

## 六、通信协议变更

### 新增/修改命令 (ESP32 → STC-B)

因为表情不再发给 STC-B，原有部分命令需要调整：

| CMD | 旧含义 | 新含义 | 说明 |
|-----|--------|--------|------|
| `0x01` | SET_EXPRESSION | **SET_AUX_DISPLAY** | 数码管显示辅助信息内容 |
| `0x07` | SET_ALL | **SET_ATMOSPHERE** | LED + 蜂鸣器 + 数码管 一次设置 |
| `0x08` | *(新增)* | **SET_DIGIT_VALUE** | 设置数码管显示的数值（时间/温度/等级）|

### SET_AUX_DISPLAY (0x01) 数据格式

```
[mode, data0, data1, ...]
```

| mode | 含义 | data 格式 |
|------|------|----------|
| `0x00` | 显示时间 | [hour_BCD, min_BCD, sec_BCD] |
| `0x01` | 显示温度 | [temp_H, temp_L] (ADC值) |
| `0x02` | 显示等级 | [level, 0x00] |
| `0x03` | 显示饱食度 | [hunger, 0x00] (0-100) |
| `0x04` | 显示自定义数字 | [d0,d1,d2,d3,d4,d5,d6,d7] (8位段码) |

### SET_ATMOSPHERE (0x07) 数据格式

```
[led_byte, beep_freq_H, beep_freq_L, beep_time_H, beep_time_L]
```

一次设置 LED 颜色 + 蜂鸣器音效（5字节）。

## 九、对现有代码的影响评估

| 模块 | 影响 | 说明 |
|------|------|------|
| STC-B 全部代码 | **几乎不变** | 只需把 SET_EXPRESSION 改为 SET_AUX_DISPLAY |
| ESP32 PetProtocol | **小改** | 修改 CMD 0x01/0x07 的含义，新增 0x08 |
| ESP32 PetState | **新增** | 增加屏幕渲染调用（原来只是发串口命令）|
| ESP32 desktop_pet.ino | **新增** | 初始化屏幕 + 在 loop 中渲染帧 |
| ESP32 expression.c (STC-B) | **简化** | 表情段码不再需要，数码管只显示数值 |

### STC-B 端需要的小改动

```c
// 旧: 接收表情ID，驱动数码管段码
case CMD_SET_EXPRESSION:
    ExprSetFace(frame->data[0]);

// 新: 接收辅助信息模式，驱动数码管显示数值
case CMD_SET_AUX_DISPLAY:
    AuxDisplaySet(frame->data, frame->len);
```

STC-B 的 `expression.c` 中表情段码表可以删除，替换为简单的数值显示函数。
